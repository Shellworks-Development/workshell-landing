Features

Everything a live game needs. Nothing it doesn't.

Roblox gives you the developer console and a crash count. Workshell gives you the rest.

Errors you can actually fix

Server and client errors are grouped by cause, with breadcrumbs, affected players and the release that introduced them.

  • Rojo sourcemaps turn ServerScriptService.Combat:42 into the file and line in your repo, at the exact commit
  • Regressions are caught when a fixed issue comes back
  • Assign teammates, discuss with @mentions, open linked GitHub issues

Follow one player from join to leave

Every session on one timeline: events, logs, errors, purchases, traced operations and exploit detections, next to that player's frame rate, ping and memory.

  • Player profiles with every session, playtime and spend
  • Attach your own metadata with Workshell.setUser
  • Optional HMAC-hashed player ids if you'd rather not store real ones

Catch exploiters in the act

Report detections from your anti-cheat with one call, and see who's flagged, how often and what you did about it.

  • Workshell.flag for speed, teleport, fly, dupes, tampered currency…
  • Workshell.protect validates and rate-limits your remotes
  • Client floods are detected automatically, and the flooder's junk errors are quarantined
Live logs

All server output and structured logs, searchable, filterable by server or player, streaming as they happen.

Performance traces

Time anything with Workshell.trace. See p50 and p95, then open a slow run span by span.

Whiteboards

Send charts, issues, sessions and traces to a shared canvas and work out what went wrong together.

  • Releases
  • Analytics
  • Discord alerts
  • Custom metrics
  • Team inbox
  • Catppuccin & more
The SDK

A few lines of Luau.

Drop the module in ReplicatedStorage and start it from a server Script. Errors, output, sessions, server health, client performance and purchases are captured from there.

  • Batched, gzipped and signed with HMAC-SHA256
  • Client data goes through a rate-limited relay, so clients can't spoof server events
  • Works with Rojo and Wally, or as a plain model file
ServerScriptService/Workshell.server.luau 
local Workshell = require(game.ReplicatedStorage.Workshell)

Workshell.init({
	url = "https://workshell.yourgame.dev",
	key = HttpService:GetSecret("workshell_key"),
})

-- Then report what matters to your game
Workshell.track("level_up", { level = 5 }, player)
Workshell.flag(player, "speed", { speed = 90 }, {
	severity = "high", action = "kicked",
})
Security

Built for games full of exploiters.

Exploiters can reach Workshell through your game's clients, and they will try. Workshell assumes it.

Signed requests

Each batch is signed over a timestamp and its body. A leaked key alone can't forge or replay data.

Flood limits

Per-player and per-server caps. Floods are dropped, recorded as detections, and can't bury real issues.

Safe rendering

Player-supplied text always renders as text, under a strict Content-Security-Policy. No XSS through your logs.

Encrypted secrets

Webhook URLs, GitHub tokens and signing secrets are encrypted at rest with AES-256-GCM.

Self-host

Your server. Your data.

Workshell is a single 16 MB binary with the dashboard built in, backed by SQLite. Add Redis when you outgrow one box. Put it behind Caddy, nginx or a Cloudflare Tunnel.

Docker 
git clone https://github.com/Shellworks-Development/workshell
cd workshell
# set WORKSHELL_PUBLIC_URL in docker-compose.yml
docker compose up -d
From source 
# needs Go 1.26+, Node 22+ and pnpm
git clone https://github.com/Shellworks-Development/workshell
cd workshell && make build
./bin/workshell   # http://localhost:8080
